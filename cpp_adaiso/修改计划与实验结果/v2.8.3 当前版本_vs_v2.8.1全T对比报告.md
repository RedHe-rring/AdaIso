解释：

```text
1. feature-aware 每个 collapse pass 需要计算角缺陷和邻接二面角，因此有固定额外成本；
2. feature-on 平均 collapse 数从 8452.9 降到 7393.0，减少约 1060 次/模型；
3. 但 feature-on 平均输出顶点数增加约 518，后续 flip/smooth/CD 评估也会受影响；
4. 因此 summary runtime 反映的是整体端到端开销，不是纯函数级开销。
```

总体看，`+4.47%` 的端到端开销较小，换来平均 CD `-13.30%` 的改善，是值得接受的。

## 哪个版本更好

按全 T 默认综合指标看，当前 feature-on 版本最好。

理由：

```text
1. 相比 v2.8.1，平均 CD 下降 11.77%，RMSE 下降 4.88%；
2. violation 从 0.089472 降到 0.039947，31/31 模型都下降；
3. 最低 Qmin 从 0.021764 提升到 0.129133，极端坏三角形风险明显降低；
4. 平均 runtime 下降 38.61%，虽然这部分也受到 mls_iterations 从 10 降到 5 的影响；
5. 与当前 feature-off 相比，feature-on 用约 4.47% 时间开销换来 13.30% 平均 CD 改善。
```

保留意见：

```text
1. 当前 feature-on 的平均 Qavg 低于 v2.8.1，说明整体三角形形状略变差；
2. T7、T67、T30 的 CD 相比 v2.8.1 明显变差，需要单独检查；
3. 当前 feature-on 相比 feature-off 的 violation 增加 0.010168，说明特征保留会牺牲一部分边长目标满足度；
4. 当前 vs v2.8.1 不是单变量消融，包含 splitFactor、flip 二面角、mls_iterations 默认值、feature-aware collapse 等多处变化。
```

建议：

```text
1. 当前默认保留 feature_aware_collapse=true；
2. 若后续优先 CD，保留 omega=0.15；
3. 若后续优先 Qmin 和 violation，可以继续全 T 跑 omega=0.25；
4. 对 T7、T30、T67 做局部可视化检查，确认 CD 变差是否来自特征端点保留、splitFactor=1.65，还是 MLS 迭代数变化。
```
