# v5.3.6 修改方向：Collapse Conflict-Region Mini-Round

## Summary

v5.3.6 只改 collapse 调度，不改 split、不改 Stage B、不改 collapse 接受准则。目标是验证 batch conflict 是否只是可被局部重试消化的调度延迟。

## Key Changes

- 版本更新到 `5.3.6`。
- 每个 collapse pass 内最多执行 2 个 mini-round：
  ```text
  mini-round 0: 全局短边候选
  mini-round 1: 只重扫上一轮 batch-conflict 区域
  ```
- conflict retry 不复用旧边；每次都基于当前网格重建 topology、重新收集短边、重新调用 `collapseRejectReason()`。
- v5.3.5 energy-only collapse 准则保持不变。
- summary JSON 增加：
  - `size_stage_collapse_conflict_mini_rounds`
  - `size_stage_collapse_conflict_retry_candidates`
  - `size_stage_collapse_conflict_retry_accepted`
  - `size_stage_collapse_conflict_retry_rejected`

## Expected Judgment

- batch conflict 应明显下降，或 collapse accepted 应上升。
- faces out/in、violation、坏角指标不应系统性恶化。
- runtime 平均不应超过 v5.3.5 的 `1.5x`，约 `90s`。
- 如果无效，下一步改 footprint 或 independent set；如果有效，下一步先给 split 加 batch-conflict 诊断。
