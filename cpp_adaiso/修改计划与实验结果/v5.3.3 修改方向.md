# v5.3.3 修改方向：Collapse 拒绝原因诊断

## Summary

v5.3.2 消融说明 split guard 不是下一步应该继续加强的方向。Stage A 的主要疑点转到 collapse：短边候选很多，但接受数量很少。

v5.3.3 不改变主算法，只增加 collapse reject reason 诊断，让 `size_stage_collapse_rejected` 可以拆解到具体门槛。

## Key Changes

- 版本更新到 `5.3.3`。
- 默认 Stage A 继续使用 `split_collapse_no_guard`。
- `summary.json` 增加 collapse 拒绝原因：
  - `size_stage_collapse_rejected_by_boundary`
  - `size_stage_collapse_rejected_by_non_manifold`
  - `size_stage_collapse_rejected_by_batch_conflict`
  - `size_stage_collapse_rejected_by_link_condition`
  - `size_stage_collapse_rejected_by_degenerate_patch`
  - `size_stage_collapse_rejected_by_target_length`
  - `size_stage_collapse_rejected_by_angle`
  - `size_stage_collapse_rejected_by_batch_duplicate`
- `size_stage_short_edge_candidates` 改为统计所有 target metric 下的短边候选；boundary 等拒绝原因在后续筛选中单独计数。
- `collapseRejectReason()` 替换内部 bool 型 `collapseValid()`，只改变诊断输出，不改变接受规则。

## Expected Use

- 如果拒绝主要来自 `target_length`，下一步改 collapse placement 或局部长度约束。
- 如果拒绝主要来自 `angle`，下一步讨论 Stage A 是否需要更弱角度安全线。
- 如果拒绝主要来自 `batch_conflict`，下一步改候选调度。
- 如果拒绝主要来自 `boundary/link_condition`，说明问题更多来自拓扑保护或边界处理。
