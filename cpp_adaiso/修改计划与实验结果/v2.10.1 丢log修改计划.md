# v2.10.1 丢 log 修改计划

## 目标

v2.10.0 已经把 `kappa` 改为 CSF 扩散后的曲率信号，并使用 `h = lambda / sqrt(kappa)` 生成 target size。但 T0 的 `target_h` 视觉上仍然接近均匀，主要原因是 robust-mean 曲率在进入 CSF 前使用了 `log1p(mean_curvature * mean_edge_length)`，再叠加 CSF 扩散和平方根映射后，曲率差异被连续压缩。

v2.10.1 的目标是只移除这一层 log 压缩，使 `kappa` 更接近无量纲平均曲率强度：

```text
raw_kappa_i = mean_curvature_i * mean_edge_length
csf_kappa = CSF(raw_kappa)
h_i = lambda / sqrt(max(csf_kappa_i, kappa_min))
```

## 代码修改

- `computeRobustMeanCurvatureField()` 中删除 `std::log1p(...)`，直接输出 `mean_curvature * mean_length`。
- 保留现有 `curvature_mode`、`csf_alpha`、`target_faces`、二分求 `lambda` 逻辑。
- 不新增 CLI 参数，不恢复 `target_min_factor`、`target_max_factor`、`target_size_gamma`、`mesh_scale`。
- target-field 诊断额外导出 `target_h_heat_observed.ply`，使用实际 `observed_h_min/observed_h_max` 着色，避免 `target_h_heat.ply` 的理论 clamp 范围把视觉差异压平。
- `vertices.csv` header 保持不变：`vertex_id,x,y,z,raw_curvature,csf_curvature,target_h`。

## 验证与实验

- 构建并运行 `adaiso_tests.exe`。
- 使用 T0、`--iters 10`、`--preprocess 0`、`--curvature-mode robust-mean`、`--csf-alpha 2.0`、`--cd-samples 100000` 运行一次 v2.10.1。
- 对比 v2.10.0 T0 的 `vertices.csv`：
  - `csf_curvature` 与 `target_h` 应保持强负相关。
  - `target_h` 的 `max/min` 和 `p95/p05` 应明显大于 v2.10.0。
  - 检查 CD、Qmin、violation 是否出现不可接受退化。
- 写实验报告，说明 target_h 是否真正拉开，以及代价是什么。
