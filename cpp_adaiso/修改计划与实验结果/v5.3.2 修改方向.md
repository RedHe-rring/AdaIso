# v5.3.2 修改方向：Stage A 诊断与消融

## 1. 背景

v5.3.0 的阶段化 remesh 让问题变得可诊断，但 Stage A 的 `split -> collapse` 出现过度加密：

```text
faces out/in = 1.485
violation = 0.05894
```

v5.3.1 改为 `collapse -> split` 并加入强 split angle guard 后，面数明显下降，但 Stage A 变成欠采样：

```text
faces out/in = 0.957
violation = 0.26262
```

因此 v5.3.2 不直接回退到 v5.3.0，也不继续强化 Stage B，而是增加 Stage A 诊断和消融策略，判断问题来自操作顺序、split guard，还是 collapse 回收能力。

## 2. 核心策略

消融前计划默认 Stage A 使用：

```text
split_collapse_weak_guard
```

也就是恢复 `split -> collapse` 的尺寸场优先顺序，但 split 只保留弱合法性 guard。

T 系列消融完成后，weak guard 没有改善坏角或 violation，因此代码默认主线改为：

```text
split_collapse_no_guard
```

weak guard 和 collapse-first 只保留为 v5.3.2 实验入口。

split 不再使用 v5.3.1 的强质量条件：

```text
after_min_angle >= before_min_angle
no new/worse obtuse
```

只保留：

```text
after patch valid
after_min_angle >= 1.0°
```

collapse 继续保留 v5.2.1 的角度安全底线：

```text
after_min_angle >= min(before_min_angle, angle_floor)
```

## 3. 消融策略

新增实验策略：

```text
split_collapse_no_guard
split_collapse_weak_guard
collapse_split_weak_guard
```

通过 CLI 实验入口：

```text
--stage-a-policy <policy>
```

该入口用于 v5.3.2 消融实验，不作为长期用户调参系统。后续确定主线策略后可以删除或隐藏。

## 4. 诊断统计

summary JSON 增加 Stage A 诊断：

```text
size_stage_long_edge_candidates
size_stage_split_accepted
size_stage_split_rejected_by_angle
size_stage_short_edge_candidates
size_stage_collapse_accepted
size_stage_collapse_rejected
size_stage_final_violation
size_stage_final_min_angle_degrees
size_stage_final_angle_lt_10_pct
size_stage_final_angle_lt_20_pct
```

这些字段用于判断：

- split 是否被角度 guard 大量拒绝。
- collapse 是否有大量候选但无法接受。
- Stage A 结束时是否已经欠采样或过度加密。
- Stage B 是否是在修复 Stage A，还是被 Stage A 的坏状态拖累。

## 5. 实验计划

运行 T 系列三组消融：

```text
A: split_collapse_no_guard
B: split_collapse_weak_guard
C: collapse_split_weak_guard
```

对比对象：

- v5.3.0
- v5.3.1
- v5.2.1

判断重点：

```text
split rejection 是否过高
long-edge residue 是否残留
collapse 是否跟不上 split
Stage A final violation 是否接近 v5.2.1/v5.3.0
Stage B 是否继续稳定改善坏角和 violation
```

## 6. 预期结论形式

v5.3.2 的目标不是直接取得最优最终指标，而是得到清晰判断：

```text
如果 no_guard 接近 v5.3.0:
  问题主要来自 split guard

如果 weak_guard 明显好于 v5.3.1:
  问题主要来自 collapse->split 顺序

如果 collapse_split_weak_guard 仍欠采样:
  collapse-first 不适合作为默认 Stage A

如果 split_collapse_weak_guard 保持低 violation 且减少坏角:
  weak guard 可作为下一版主线
```
