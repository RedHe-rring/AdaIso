## 1. 实验设置

本实验将目标面数 N 压到 2000，对 `T0.off` 到 `T5.off` 分别运行 v5.0.0、v5.0.1、v5.0.2，检查低面数预算下两次修改是否有收益。

- `N=2000` interpreted as `--target-faces 2000`.
- Versions: v5.0.0 from tag `v5.0.0`, v5.0.1 from tag `v5.0.1`, v5.0.2 from current uncommitted workspace.
- Common command options: `--target-faces 2000 --iters 10 --preprocess 0 --curvature-mode robust-mean --csf-alpha 2.0 --gt <same input> --cd-samples 100000 --export-target-field <case>/target_field --summary-json <case>/summary.json --quiet`.
- Result root: `cpp_adaiso/results/v5_N2000_T0_T5_compare/`.
- Comparison CSV: `cpp_adaiso/results/v5_N2000_T0_T5_compare/comparison.csv`.

Note: v5.0.2 changes ratio/violation semantics to `target_metric_edge_length`; v5.0.0/v5.0.1 use the older endpoint-target ratio. Cross-version violation is therefore diagnostic, not a strict same-unit comparison.

## 5. 解读

- CD is the primary geometry metric in this report. `CD winner` is the version with the lowest `chamfer_distance` for each model.
- v5.0.1 isolates target metric split placement. v5.0.2 adds metric edge length decisions for split/collapse/flip guards.
- If v5.0.2 lowers CD within 1% of the best older version and does not materially hurt qmin or face-budget error, it is marked `benefit`; conflicting signals are marked `mixed`.
- Low N changes the question: matching the 2000-face budget and preserving qmin can matter as much as reducing local edge-ratio violation.

- CD winner：T0/T1/T3 是 v5.0.1，T2/T4/T5 是 v5.0.0。

报告里已按 CD、qmin、面数预算误差、operation count 分开解释。

v5.0.2 变差的主因不是 metric 公式本身错，而是 **把旧的 `splitFactor=1.65 / collapseFactor=0.8` 直接搬到新 metric length 口径后，阈值没有重新标定**。在 N=2000 低面数预算下，这个影响被放大了。

**1. v5.0.2 系统性生成更粗的网格**

N=2000 下平均输出面数：

| version | avg faces | avg abs(faces-2000) | avg CD |
|---|---:|---:|---:|
| v5.0.0 | 1809 | 190.7 | 8.245e-05 |
| v5.0.1 | 1807 | 193.3 | 8.240e-05 |
| v5.0.2 | 1592 | 408.3 | 9.559e-05 |

v5.0.2 平均比旧版本少约 215 个面，离 2000 更远。CD 平均比 v5.0.1 高约 16%。这说明它不是细节位置略差，而是整体采样密度不足。

**2. 新 metric 判据让 split 更难触发、collapse 更容易触发**

旧 v5.0.1 code 口径大致是：

```text
split:    length / min(h_a, h_b) > 1.65
collapse: length / min(h_a, h_b) < 0.8
```

v5.0.2 改成：

```text
M = length / logMean(h_a, h_b)
split:    M > 1.65
collapse: M < 0.8
```

其中：

```text
logMean(h_a, h_b) = (h_b - h_a) / (log(h_b) - log(h_a))
```

当 `h_a != h_b` 时，`logMean(h_a, h_b)` 大于 `min(h_a, h_b)`。所以同一条边上：

```text
length / logMean < length / min(h)
```

结果就是：

- split 更少：很多旧版本认为“太长”的边，在 v5.0.2 里不再 split。
- collapse 更强：collapse 的等价欧氏阈值变成 `0.8 * logMean`，比旧的 `0.8 * min(h)` 更宽松。

N=2000 的操作数据也吻合：

| model | v5.0.1 split | v5.0.2 split | v5.0.1 collapse | v5.0.2 collapse |
|---|---:|---:|---:|---:|
| T0 | 43 | 16 | 9154 | 9220 |
| T1 | 60 | 20 | 9151 | 9221 |
| T2 | 43 | 10 | 9125 | 9205 |
| T3 | 45 | 11 | 8584 | 8670 |
| T4 | 100 | 41 | 9166 | 9222 |
| T5 | 66 | 21 | 9195 | 9244 |

v5.0.2 的 split 大幅减少，collapse 反而增加，最终自然更粗。

**3. violation 下降是“新口径下更满足目标”，不是几何更好**

v5.0.2 平均 final violation 从旧版本约 `0.059` 降到 `0.043`，看起来更好。但这个指标的语义已经变了：

- v5.0.0/v5.0.1：`edge_length / min(endpoint target_h)`
- v5.0.2：`target_metric_edge_length`

所以 v5.0.2 是在自己的 metric 判据下更规整，但这个规整对应的是更宽松的有效长度尺度，导致输出更粗，CD 更高。

**4. qmin 改善不能抵消 CD 和预算误差**

v5.0.2 在 T0-T3 上 qmin 明显提高，这是粗化的常见副作用：少一些小边和局部高密度结构后，三角形质量可能更好。但：

- T4/T5 qmin 反而下降。
- 所有模型 CD 都变差。
- 所有模型输出面数都明显低于旧版本。

所以这不是全面质量收益，而是“牺牲采样密度换来部分质量指标改善”。

**结论**

v5.0.2 更差的核心原因是：`M_ab` 改变了长度尺度，但 `splitFactor/collapseFactor` 没有重新校准。旧的 `1.65/0.8` 在 `length/min(h)` 口径下较合适，迁移到 `length/logMean(h)` 后会抑制 split、放宽 collapse，N=2000 时直接造成欠采样。

下一步最合理不是回滚 metric 判据，而是扫描新口径下的 hysteresis，例如：

```text
splitFactor:    1.25, 1.35, 1.45, 1.55
collapseFactor: 0.55, 0.65, 0.75
```

目标是让输出 faces 回到接近 1800-2000，同时观察 CD 是否恢复。
