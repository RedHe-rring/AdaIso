在 surface remeshing 中，“特征”最好区分为两类。第一类是光滑曲面内部的几何细节，例如高曲率区域、ridge 和 valley。这类特征的主要问题是采样密度不足，因此可以根据曲率、local feature size 或其他几何先验构建目标尺寸场，在几何变化剧烈的位置减小目标边长。

第二类是 crease、corner 和 boundary 等非光滑硬特征。它们并不只是“曲率很大”的区域，而是曲面的低维奇异结构：crease 是一维 feature curve，corner 是零维 feature point。普通的标量尺寸场只能控制局部网格密度，不能保证网格边与 crease 对齐，也不能保证 corner、feature connectivity 和 patch adjacency 在 split、collapse、flip 与 smoothing 后仍然存在。因此，硬特征通常需要作为显式约束参与 remeshing。

尺寸场和特征约束并不是互斥的。曲面 patch 内可以使用二维尺寸场控制采样密度，crease 上也可以定义一维尺寸场控制 feature curve 的采样间距；但 feature curve 上的尺寸场只决定“沿曲线采多少点”，显式约束则决定“这些点和边必须留在曲线上”。实现上，可以将输入几何划分为二维 surface patches、一维 feature curves 和零维 corners，并针对不同维度限制局部操作：普通顶点在曲面上移动，crease 顶点只能沿 feature curve 移动，corner 固定；feature edge 可以被细分，但不能被随意 flip，collapse 也必须保持 feature graph 的拓扑和几何误差。

因此，较合理的框架是将几何尺寸控制与硬特征保护分开建模：前者由 sizing field 负责，后者由 feature detection、patch classification 和 constraint-aware remeshing operators 负责。两者共同作用，而不是试图通过单一尺寸场同时解决采样密度和特征拓扑保持问题。




是的，应该分开。你现在这个判断已经接近一个比较清晰的论文方向了。

我建议把 feature 分成两类：

```text
1. soft geometric detail / high-curvature region
   例如光滑曲面上的高曲率、圆角、小半径弯曲、凸起。

2. hard feature / non-smooth structure
   例如 crease、corner、boundary、薄片边缘、尖端、CAD 折线。
```

这两类不应该用同一种机制处理。

**高曲率区域：用尺寸场**
高曲率但仍然光滑的区域，目标是“采样更密”。这正适合尺寸场：

```text
curvature high -> target_h small -> more vertices
```

这里不一定要锁点、不一定要禁止 flip/collapse。只要局部密度足够，remesh 后仍然可以是 isotropic 的。

**crease/corner/boundary：用 feature constraints**
硬特征的问题不是“点不够密”这么简单，而是**拓扑和几何约束**问题。比如一条 sharp crease，如果你只让尺寸场变小，算法仍然可能：

```text
collapse 掉 crease 上的点
flip 掉沿 crease 的边
smooth 把 crease 拉圆
project 到错误的光滑面片上
```

所以硬特征需要额外约束：

```text
boundary/corner 不动或强约束
crease vertex 只能沿 crease 方向移动
collapse 不能跨 feature
flip 不能破坏 feature edge
smooth 不能跨 feature 混合
projection 应该投回 feature curve / feature side
```

**能不能只靠尺寸场保护硬特征？**
理论上可以“缓解”，但很难“保证”。原因是尺寸场只控制长度，不控制：

```text
边是否沿 crease 排列
点是否留在 crease 上
两侧曲面是否被 smooth 混合
corner 是否被 collapse 掉
```

你可以把 crease 附近 `target_h` 设得很小，这会让算法保留更多点，但它仍然可能把硬边变成一串偏离 crease 的小三角形。结果看起来更密，但特征还是糊了。

所以更合理的框架是：

```text
sizing field = 保护 soft detail
feature constraints = 保护 hard feature
```

论文里可以把这变成一个很清晰的主张：

> Curvature-derived sizing preserves smooth geometric detail, while explicit feature-aware local operators preserve non-smooth structures.

下一步实验也应该分开算：

```text
global error
soft-detail error / high-curvature error
hard-feature error / crease-corner-boundary error
smooth-region error
```

这样你能判断问题来源：

```text
high-curvature error 高 -> 尺寸场/曲率估计问题
hard-feature error 高 -> collapse/flip/smooth/projection 约束问题
smooth error 高 -> 过度简化或 projection 问题
```

我会把工具也改成这套分类，而不是只有 `feature / near_feature / smooth`：

```text
hard_feature
near_hard_feature
soft_feature
near_soft_feature
smooth
```

这样后面方法设计和实验表都会更清楚。
